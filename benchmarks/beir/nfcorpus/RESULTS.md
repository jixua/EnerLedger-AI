# BEIR NFCorpus 本地检索对照实验

2026-09-28 在本机 Docker 的两个隔离 Compose 项目中运行。使用 BEIR NFCorpus
官方压缩包（MD5 `a89dba18a62ef92f7d323ec890a0d38d`），完整导入 3,633 篇
文档，对 test split 的 323 个问题和 12,334 条正相关标注评分。两边均确认全部
3,633 篇解析成功后才运行检索；所有分数是**源文档级**的 `@10` 宏平均值，
由仓库内同一个 `score_nfcorpus` 函数计算。排名、逐题分数和语料 SHA-256 保存在
`results/` 下的 JSON 文件中。

## 运行配置

| 项目 | 本项目 EnerLedger | WeKnora 512 字符分块配置 |
| --- | --- | --- |
| 版本 | 评测时源码 `a5558a175d8e6bddacb5ffa5749954cd90601ff6`；API 镜像 `sha256:5b2ce0ecbd6a01c8a95115ad51f1be18020f994cb21a2d9c34db987241c4fcc5` | 官方 `v0.8.2` 镜像，源码修订 `3e8b0bfc80b845b2d4b2ed683994748741450a97` |
| 隔离环境 | `energy-carbon-nfcorpus`，API 端口 `18000` | `weknora-nfcorpus`，API 端口 `18080` |
| Dense 模型 | `qwen3.7-text-embedding`，2048 维 | 同一模型及 2048 维，显式启用维度覆盖 |
| 其他检索 | Doubao Sparse Embedding + Manticore BM25，与 Dense 融合 | WeKnora 内置关键词检索与 Dense 混合 |
| 分块设置 | 512 token 上限、64 token 重叠；实际 4,024 个向量分块 | 512 字符、50 字符重叠；实际 18,237 个向量分块 |
| API 与候选窗口 | `/api/v1/recall`，融合后 64 个分块候选 | `/api/v1/knowledge-bases/{id}/hybrid-search`，`match_count=64`、跳过上下文扩展 |
| 评分 | 按源文档 ID 去重后的前 10 篇 | 同一规则 |

WeKnora 的 512/50 是本次显式设定的实验参数；其源码当前的默认重叠值为
80 字符，不能把本组数值称作未经配置的官方默认成绩。

另建 WeKnora `BEIR-NFCorpus-test-2048chars` 知识库，只把分块设置改为
2,048 字符及 256 字符重叠，其余模型、语料、检索入口和候选窗口不变。该库
也有 3,633 篇解析成功，实际产生 7,768 个 2048 维向量分块。它比首轮
分块配置的 18,237 个更接近本项目的 4,024 个，但仍约为本项目的 1.93 倍，
因此属于**分块尺度敏感性测试**，不是完全相同分块的算法消融。

WeKnora 把同类型、同正文哈希的文件视为重复。官方语料恰有 40 对不同 ID、
正文完全相同的文档；为保留全部文档，每对第二篇在 WeKnora 中以 `.txt` 上传，
其余以 `.md` 上传。两种文件正文的字节完全相同，具体见适配脚本。

## 512 字符分块比较

| 指标 @10 | EnerLedger | WeKnora | 差值（EnerLedger − WeKnora） | 逐题配对 bootstrap 95% 区间 |
| --- | ---: | ---: | ---: | ---: |
| Precision | 0.3080 | 0.2904 | +0.0176 | [+0.0056, +0.0300] |
| Recall | 0.2014 | 0.1986 | +0.0029 | [−0.0076, +0.0134] |
| NDCG | 0.4142 | 0.3961 | +0.0181 | [+0.0044, +0.0317] |
| MRR | 0.6218 | 0.6078 | +0.0140 | [−0.0180, +0.0452] |
| MAP | 0.1606 | 0.1576 | +0.0030 | [−0.0036, +0.0095] |

区间采用 323 个问题作为配对单位，有放回重采样 10,000 次，随机种子
`20260928`，报告百分位数区间。首轮配置下，本项目五项点估计均高一些；
Precision 与 NDCG 的差值区间为正，其余三项区间跨零。每个问题两边都返回
至少 10 个不同源文档；平均 64 个分块候选覆盖的不同文档数分别为 61.09
和 35.20。该差异与两套分块尺度不同有关，因此另做近似同粒度分块对照。

| Recall | 0.2014 | 0.1948 | +0.0066 | [−0.0048, +0.0175] |
| NDCG | 0.4142 | 0.3918 | +0.0224 | [+0.0094, +0.0360] |
| MRR | 0.6218 | 0.6000 | +0.0217 | [−0.0075, +0.0516] |
| MAP | 0.1606 | 0.1511 | +0.0095 | [+0.0016, +0.0180] |

该组 64 个分块候选平均覆盖 44.25 篇不同源文档，处于 WeKnora 512 字符配置
的 35.20 与本项目的 61.09 之间。两组 WeKnora 分块配置之间五项差值的
配对区间均跨零；本实验未观察到仅调整这个分块尺度就改变排序结论。
这不等于证明其他切分参数、模型或数据领域下也会有同样结果。

## 解释范围

这衡量的是当前两套产品检索链路在一份**英文营养和生物医学**公开数据上的
文档级准确性。Dense 模型、语料、问题、正相关标注、候选窗口和评分器一致；
切分、稀疏检索、融合算法及向量存储仍属各产品实现的一部分。它不能直接说明
中文能碳领域、答案生成质量、检索延迟或资源成本哪个更好。这里的分数也不是
腾讯官方发布的 WeKnora 基准分数。

## 复核文件

- `results/enerledger-k10.json`：本项目原始排名和逐题指标。
- `results/weknora-k10.json`：WeKnora 512 字符、50 字符重叠配置的原始排名和指标。
- `results/weknora-2048chars-k10.json`：WeKnora 2,048 字符分块的原始排名和指标。
- `results/compare-512chars-k10.json`、`results/compare-2048chars-k10.json`
  和 `results/compare-weknora-chunking-k10.json`：逐题配对差值及置信区间。

复算使用 `scripts/nfcorpus_retrieval_benchmark.py score` 和
`scripts/compare_nfcorpus_reports.py`；不需要访问原来的 Docker 容器。
