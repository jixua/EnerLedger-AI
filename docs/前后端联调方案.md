# 能碳会计 AI 智能体前后端联调方案

## 1. 联调目标

验证 Web 前端不依赖预览数据，直接使用 Python API 完成以下闭环：

1. 模型配置查询、创建、更新、启停和删除。
2. 数据集创建、查询、更新、删除及模型绑定。
3. 文档上传、统一队列查询、状态轮询、改名、失败重试、重新解析和删除。
4. BM25、Sparse、Dense 三路召回及来源字段展示。
5. SSE 对话的 `stream_started → recall_done → answer_delta → answer_done` 事件闭环。
6. MySQL、MinIO、Qdrant、Manticore、解析队列与 worker 可观察状态。

本方案不增加业务表。解析队列继续使用 `document` 表的状态、可用时间和 lease 字段。

## 2. 环境与启动顺序

| 层级 | 地址 | 要求 |
| --- | --- | --- |
| 前端 | `http://127.0.0.1:4175` | `VITE_DEMO_MODE=false` |
| Python API | `http://127.0.0.1:8000` | `/health/live` 返回 200 |
| MySQL | Compose 内 `mysql:3306` | Alembic 已升级到 head |
| MinIO | Compose 内 `minio:9000` | 原文件桶与解析产物桶存在 |
| Qdrant | Compose 内 `qdrant:6333` | `/readyz` 可用 |
| Manticore | Compose 内 `manticore:9306` | SQL 端口可连接 |
| parse-worker | Compose 服务 | 能消费 `QUEUED` 文档 |

启动及检查：

```bash
docker compose up --build -d
docker compose ps
curl -fsS http://127.0.0.1:8000/health/live
curl -fsS -H 'X-User-Id: 1' http://127.0.0.1:8000/api/v1/system/status
cd frontend && npm run dev -- --host 0.0.0.0 --port 4175 --strictPort
```

本地开发由 Vite 将 `/api` 和 `/health` 代理到 `VITE_BACKEND_PROXY_TARGET`。前后端分域部署时，前端设置 `VITE_API_BASE_URL`，后端通过 `CORS_ALLOW_ORIGINS` 明确允许前端来源。

## 3. 契约检查

- 所有业务请求携带 `X-User-Id`；健康存活检查除外。
- API 错误统一从 FastAPI 的 `detail` 提取，不把 HTTP 200 以外的响应当成业务成功。
- 文档上传固定返回 `202 + DocumentRead`，初始状态为 `QUEUED`。
- 前端仅在显式配置 `VITE_DEMO_MODE=true` 时使用预览数据；网络失败必须展示真实错误。
- `DocumentRead` 不返回 `lease_token`、`lease_owner`；`LLMConfigRead` 不返回明文 Key。
- SSE data 必须为 JSON，流必须以 `answer_done` 或 `error` 结束。

## 4. 测试矩阵

| 编号 | 场景 | 操作 | 预期 |
| --- | --- | --- | --- |
| C01 | API 存活 | GET `/health/live` | 200，`status=ok` |
| C02 | 依赖状态 | GET `/api/v1/system/status` | 返回六类组件状态和队列计数 |
| C03 | 模型列表 | GET `/api/v1/llm/configs` | 只返回当前用户可见配置，Key 为掩码 |
| C04 | 数据集生命周期 | POST → GET → PATCH → DELETE | 字段持久化，非空数据集禁止删除 |
| C05 | 文档上传 | POST multipart | 202，状态 `QUEUED`，Location 可查询 |
| C06 | 队列轮询 | GET `/api/v1/documents` | 前端自动观察 `QUEUED/PROCESSING/READY/FAILED` |
| C07 | 文档改名 | PATCH `/api/v1/documents/{id}` | 仅展示名改变，格式和对象键不变 |
| C08 | 失败恢复 | retry / reparse | 重试不加版本，重新解析版本加一 |
| C09 | 三路召回 | POST `/api/v1/recall` | 命中含文件名、页码、版本、片段和三路分数 |
| C10 | 流式对话 | POST `/api/v1/rag/stream` | 事件顺序正确，回答和引用可展示 |
| C11 | 无召回上下文 | 查询无关问题或空索引数据集 | 仍返回固定说明和 `answer_done` |
| C12 | 后端不可达 | 停止 API 后刷新前端 | 明确显示离线，不出现预览业务数据 |
| C13 | CORS | 使用允许来源发 OPTIONS | 允许 `X-User-Id`、JSON 和 SSE |
| C14 | 清理 | 删除测试文档、测试数据集 | MySQL、对象与索引不残留测试数据 |

## 5. 自动化执行

```bash
# 后端源码、契约与行为测试
uv run python -m compileall -q app migrations
uv run ruff check app/main.py app/api/documents.py app/api/system.py \
  scripts/fullstack_smoke.py tests/test_frontend_backend_contract.py
uv run pytest

# 前端请求契约、Sites worker 和生产构建
cd frontend
npm test
npm run build

# 已配置模型情况下的真实控制面 CRUD 冒烟
cd ..
uv run python scripts/fullstack_smoke.py

# 真实解析、三路召回和 SSE 数据面闭环
FULLSTACK_SMOKE_FILE=tests/fixtures/fullstack-smoke.html \
  uv run python scripts/fullstack_smoke.py
```

脚本使用唯一临时数据集名称，并在终态后删除文档和数据集。若进程在文档仍为活跃状态时被中断，应先等待其进入 `READY` 或 `FAILED`，再执行删除，避免绕过队列 lease 约束。

## 6. 通过标准

- Python 全量测试、本轮改动范围 Ruff、前端测试和生产构建全部通过。
- 控制面真实 CRUD 冒烟通过并完成数据清理。
- 测试文档进入 `READY`，三路召回至少返回一个命中。
- SSE 至少出现 `recall_done` 和 `answer_done`，浏览器展示回答与来源。
- 前端浏览器控制台无应用 error/warning；网络请求不访问 `example.invalid`。
- 系统状态页展示来自真实 `/api/v1/system/status` 的结果，而不是静态卡片状态。
