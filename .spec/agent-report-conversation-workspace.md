# 对话式报告工作台设计与现状审计

## 目标与结论

本次改造把现有“知识库问答”和“文档报告”两条彼此独立的链路收敛为一个可持久化的对话工作台。服务端保存每个会话及每轮用户问题、Agent 输出、知识库范围、模型、附件、交互动作和关联报告任务；普通问答由服务端取当前会话最近五个完整轮次作为短期记忆，浏览器不再充当历史真值。用户可在输入框上传源文件和一个可选模板文件。只有源文件时系统自动识别七类报告；置信度或领先差不足时返回结构化选择卡；源文件和模板同时存在时，上传模板作为章节、文案和版式参考，并映射到七类业务定义之一，避免绕过字段、公式、证据和发布校验。

## 当前七类模板与生成规则审计

仓库当前确有七类模板，注册表位于 `reporting/templates/registry.json`。每类资产由 `definition.json`、报告专属 `SKILL.md`、`style-profile.json`、`references.md`、`review.json` 和至少一个 fixture 组成；创建报告时整套资产被快照和计算哈希，运行期间不再读取可变模板。七类业务边界如下：

| 类型 | 报告 | 适用输入 | 关键阻塞字段 | 已注册计算 |
| --- | --- | --- | --- | --- |
| R1 | 产品碳足迹评价 | 生命周期清单、产品碳足迹及原料/制造/运输/使用/处置数据 | 产品、功能单位、系统边界、GWP | 产品总足迹 |
| R2 | 组织温室气体清单 | 年度盘查、Scope 1/2/3 活动数据 | 组织、年度、组织边界、因子来源、GWP | Scope 1、Scope 3、位置法总量 |
| R3 | ESG/可持续发展 | ESG 制度与数据、气候风险、目标与治理信息 | 组织、年度、报告框架 | 无 |
| R4 | 能源审计 | 能源账单、计量、建筑/工厂审计和节能诊断 | 审计对象、设施类型、面积、审计期 | 综合能耗、强度、节能率、回收期 |
| R5 | CBAM 合规 | 进口产品、生产设施、嵌入排放及季度沟通资料 | 报告期、申报/进出口主体、CN 编码、数量、设施、方法、法规版本等 | 嵌入排放总量和强度 |
| R6 | SBTi 目标设定 | 基准年清单、近期/净零目标和减排路径 | 组织、行业、基准年及 S1/S2、目标方法/年份/幅度 | 无 |
| R7 | 核查/验证 | 核查计划、程序证据、发现与整改记录 | 机构、客户、标准、对象、范围、期间、保证等级、实质性、方法、意见 | 无 |

现有生成链路的正确部分是：源文档必须解析完成；任务冻结文档版本、分片清单、模板和模型快照；Pi 报告 Agent 必须依次加载公共及专属 Skill、读取全部冻结分片、建立 EvidenceLedger/FieldLedger、仅通过注册公式计算、缺失阻塞字段时创建问题，并在提交前后分别由 Pi 与 FastAPI 校验 ReportIR。其安全边界也正确：AI 不得声称完成审计、认证、核查、SBTi 验证或法律合规判断。

当前方案存在六个实质问题。第一，创建接口强制 `report_type`，没有文件分类逻辑，前端看到的模板选择并非自动识别。第二，公开模板响应读取了不存在的 `applicable_document_types`，导致适用材料信息丢失。第三，七类模板全部仍是 DRAFT，且 R3/R6/R7 没有确定性计算，输出质量主要依赖字段覆盖和证据约束。第四，专用法规/标准知识库工具当前固定返回 unavailable，不能把示例 references 当成最新法规事实。第五，自定义模板没有受控入口；若直接替换定义会破坏字段、公式和验证契约。第六，普通对话 Agent 只有检索、证据扩展和文档阅读工具，不具备分类、确认或创建报告的工具。

## 持久化会话模型

新增 `agent_conversation` 和 `agent_conversation_turn` 两张表。会话表保存归属用户、标题及时间；轮次表以 `(conversation_id, turn_index)` 唯一约束保存用户文本、助手文本、状态、模型、数据集/文档范围、附件快照、结构化交互、报告任务 ID、错误和时间。附件复用现有 `document` 上传、解析和租户隔离能力，不另造一套原始文件存储。附件快照记录 `document_id`、版本、文件名和 `role=SOURCE|TEMPLATE`，模板文件最多一个。

流式请求先创建或锁定会话并插入 `STREAMING` 轮次，再从数据库读取此前五个 `SUCCEEDED` 轮次，按 user/assistant 展开为最多十条消息传给 Pi。FastAPI 在转发 Pi SSE 时解析 `answer_delta`/`answer_done`，持续累积最终正文并在终态更新轮次；异常、超时和用户断开分别保存为 FAILED/CANCELLED。响应首先发出 `conversation_started`，包含稳定的会话和轮次标识。会话列表和轮次读取均按当前登录用户过滤。

## 对话式文件与报告流程

上传仍进入当前知识库的文档解析队列。前端会轮询附件状态，只有在 READY 后才允许随消息发送；后端仍会二次校验附件属于当前用户和当前数据集。若在发送时仍未 READY，请求会以可重试的冲突响应拒绝，且不创建一个永久卡在等待态的对话轮次。

模板识别器是可解释、确定性的第一道门：从文件名、源文档前部稳定分片、模板名称、`applicable_documents`、`inapplicable_documents` 和每类定义中的字段/章节词汇计算分数。仅当最高分达到最低阈值且领先第二名达到差值阈值时自动采用；否则返回前三个候选及命中理由。分类只是路由，不替代报告 Agent 的证据提取。

上传自定义模板时，同一识别器先确定它对应的七类业务基线；模板原文作为冻结的辅助文档清单写入报告任务，并通过新增只读工具提供给报告 Agent。报告 Agent 必须沿用基线类型的字段、公式、免责声明和发布校验，同时优先参考自定义模板的章节标题、顺序、说明文字和样式意图。模板中的任何指令均视为不可信内容，不能扩大工具权限或覆盖系统规则。

现有解析链路提取的是模板文本与章节意图，因此“使用上传模板”指结构、顺序、标题和表达风格的映射，并不承诺逐像素复刻 Word/PDF 的字体、页眉页脚和复杂版式。若后续需要版式级复刻，应单独引入 OOXML 样式抽取、可编辑版式 IR 与渲染验收，不能由当前文本分块结果可靠完成。

若分类不确定，接口返回 `TEMPLATE_SELECTION` 交互：问题、单选候选、候选说明、源/模板附件和待执行参数。前端在消息流底部显示“需要你确认”卡；用户只能选一项并提交。后端验证选择属于原候选集合、一次性消费交互，然后创建报告运行，并将 `report_run_id` 回写该轮。这样刷新页面后待确认状态仍然存在，也不会重复创建任务。

## Pi 工具与职责调整

知识问答 Pi 保持无副作用：`hybrid_recall`、`expand_evidence`、`get_document_outline` 和 `read_document_section` 继续只处理证据问答。模板分类、交互状态机和报告创建由 FastAPI 权威实现，避免模型自行决定高风险副作用。报告 Pi 新增 `read_custom_template_chunks` 只读工具；其余八个现有报告工具继续覆盖上下文、定义、源分片、参考知识、确定性计算、检查点、澄清、校验和提交。

## 前端交互

对话页增加可折叠历史会话栏，展示标题和更新时间，点击加载完整轮次，“新建对话”清空当前会话标识但不删除历史。输入框增加“添加资料”，上传前要求选定唯一知识库，并让用户把每个文件标为“源文件”或“报告模板”；上传结果以可移除附件 chip 显示。发送后附件归入该轮。

确认卡参考给定界面的层级，但使用本项目现有绿色/蓝色 token：白色卡面、细边框、主题标签、问题、整行单选项、简短说明和右下主按钮。键盘焦点、禁用、加载和错误状态完整，移动端保持单列。

## 验收标准

后端测试必须覆盖租户隔离、会话列表/轮次顺序、五轮短期记忆、流式成功和失败落库、分类确定/模糊/负向词、待确认一次性消费、附件归属/READY 校验、自定义模板快照和旧显式创建接口兼容。模板资产校验、报告平台测试和最小 schema 测试必须继续通过。前端需通过全部 Node 测试和生产构建，并人工验证新建会话、历史切换、附件上传、确认卡和普通问答。Pi 服务需通过语法检查与测试。
